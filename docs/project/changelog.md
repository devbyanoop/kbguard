# Changelog

All notable changes to kbguard are recorded here, following [Keep a Changelog](https://keepachangelog.com/) conventions. Nothing has been released yet — everything below is under `Unreleased`.

## [Unreleased]

### Added
- Project scaffold: `pyproject.toml` (packaging, extras per vector store, `ruff`/`mypy`/`pytest` config), `.gitignore`, `docker-compose.yml` for pgvector/Qdrant test fixtures.
- `models.py`: `Chunk`, `Finding`, `EvalResult`, `Snapshot`, and the `compute_fingerprint()` algorithm used by `diff` and suppressions.
- `config.py`: pydantic schema for `kbguard.yaml` — strict (unknown fields rejected), minimal-by-default (only `store` required), secrets referenced by environment-variable name and resolved only at point of use.
- `adapters/base.py`: the `VectorStoreAdapter` Protocol (five methods: `connect`, `collections`, `count`, `iter_chunks`, `search`), plus `src/kbguard/py.typed` so the Protocol type-checks for external consumers, not just within this repo.
- `registry.py`: entry-point based plugin discovery for adapters (`load_adapter`, `list_available`) — the mechanism that lets a new vector store be added as one file with no changes to kbguard's own source.
- `adapters/chroma.py`: the first working adapter, registered as a real plugin and verified end-to-end (`load_adapter("chroma")` resolves through the actual installed package metadata, not a mock). In-process, no server required.
- `contract_tests/`: the shared, backend-agnostic suite every adapter must pass (count/iteration, id stability, best-match-first search ordering, text/metadata/embedding round-trip), parametrized over a seeder+settings map so adding a new adapter to the suite is a seeder function + one entry, no new test code. Passing against Chroma, pgvector, and Qdrant.
- `ingest/metadata.py`: fills `Chunk`'s standard fields from a chunk's own raw metadata via dotted-path `metadata_map` lookups (e.g. `meta.last_modified`), with explicit type coercion (position → int, updated_at → datetime, handling both epoch numbers and ISO-8601 strings including a `Z` suffix on Python 3.10, not just 3.11+) and a `validate_metadata_map` check that rejects an unrecognized target field instead of silently ignoring it.
- `ingest/embeddings.py`: `get_embedder` (text → vector, lazy-loaded so an optional extra's library is never imported — and never even needed — unless a chunk actually lacks a stored embedding) and `embed_chunk` (the separate reuse-or-recompute policy). Supports `sentence-transformers` (local) and `litellm` (hosted/local-server, e.g. Ollama) providers.
- `ingest/exporter.py`: `export_chunks` sequences `iter_chunks()` → `apply_metadata_map` → `embed_chunk` into one generator. Split into a plain outer function (runs `validate_metadata_map` immediately on call) wrapping an inner generator (the actual per-chunk `yield` loop), since a single generator function wouldn't run *any* of its body — including validation — until first iterated, which would have meant a bad `metadata_map` silently raising nothing until some arbitrary, possibly-never later point. `with_embeddings` passed to the adapter is wired directly to `reuse_stored`, so a store is never asked for vectors that are just going to be discarded.
- `ingest/snapshot.py`: `SnapshotWriter`/`SnapshotReader` — the on-disk snapshot format (`chunks.parquet`, `vectors.npy`, `index.sqlite`, `findings.jsonl`, `manifest.json`) every check/eval/diff will read from. Fails fast on a missing embedding, a dimension mismatch, a duplicate chunk id, a duplicate finding fingerprint, or any write after `close()`.
- `cli.py`: `kbguard scan --collection <name> --config <path>`, the first real CLI command, wiring config → registry → adapter → exporter → snapshot together. Known user-facing error types (bad config, unknown adapter, bad metadata_map, missing credentials, a snapshot invariant violation) print one clear line, not a traceback.
- `examples/policy_corpus/`: a 16-chunk synthetic demo corpus with planted problems for every Week 2 check to eventually find, plus a ready-to-use `kbguard.yaml`. Verified end-to-end with a real `kbguard scan` run, not just in tests.
- `adapters/pgvector.py`: keyset pagination (not `OFFSET` — a real risk on a live, multi-writer table). Table/column names come from config, validated against a strict SQL-identifier allowlist before use (can't be parameterized like values can). Never runs DDL — `CREATE EXTENSION`/`CREATE TABLE` stay outside the adapter entirely, enforced structurally (no write method exists on it at all), not just by convention. `search(..., filters=...)` raises `NotImplementedError` rather than silently returning unfiltered results.
- `adapters/qdrant.py`: scroll-cursor pagination; uses `query_points()`, since `.search()` doesn't exist on the installed client version. An optional `id_field` setting lets a client's real external id (preserved in the payload, since Qdrant point ids must be an unsigned int or UUID) override the native id `Chunk.id` would otherwise default to. `text_field` (`store.text_field` in `kbguard.yaml`) reads chunk text out of the payload, since Qdrant has no distinct text storage.
- Both new adapters verified against real containers (`pgvector/pgvector:pg16`, `qdrant/qdrant`) via `contract_tests/`, dedicated adapter-specific test files, and a real `kbguard scan` run each — not mocked at any layer.
- `checks/base.py`: the `Check` Protocol + `CheckContext`. `registry.py` gained a `checks` entry-point group (`load_check`, `list_available("checks")`), the same plugin mechanism adapters use.
- `checks/duplicates.py`: exact-duplicate detection (normalized-text hash) and near-duplicate detection (`faiss` `IndexFlatIP` cosine-similarity candidates on L2-normalized vectors, confirmed only when `datasketch` word-set Jaccard also passes), union-find clustering so a transitive chain of near-duplicates becomes one finding, severity escalated to `error` across sources regardless of configured base severity. Verified against the real example corpus — finds exactly the two planted duplicate pairs.
- `SnapshotReader.vectors()`: bulk, id-aligned access to every chunk's vector — deferred at the end of Week 1 specifically until `duplicates.py` (its first real caller) existed, rather than built speculatively.
- `checks/stale_versions.py`: groups chunks into document families by `title` (falling back to a normalized source/filename stem with one trailing version marker stripped), orders by `updated_at` (falling back to `version` string), flags every member but the newest, escalates severity to `error` via a self-retrieval probe against the *live* store (not the snapshot) using the stale chunk's own embedding as the query. Verified against the real example corpus with a live Chroma connection — the planted pair is found and genuinely escalates.
- `judge/client.py` + `judge/cache.py`: provider-neutral `JudgeClient.ask_json(prompt, schema_hint) -> dict` via `litellm`'s model-string routing (same call shape for a hosted model or a local `ollama/*` model). JSON-only output requested via `response_format={"type": "json_object"}`, with exactly one retry on malformed JSON (raises `JudgeError` after 2 failed attempts, never a silent `None`). Responses cached by a `sha256` hash of model+prompt+schema_hint in `JudgeCache`, a sqlite file living inside the snapshot's own directory, per spec section 10. `litellm` imported lazily inside the one method that actually calls out, not at module level, matching `ingest/embeddings.py`'s `_litellm_embedder` pattern. 14 tests using a fake `litellm` module installed via `sys.modules` (same technique as `test_ingest_embeddings.py`), including one asserting the fake backend's call count doesn't increase on a cache hit.
- `checks/chunking_damage.py`: six deterministic rules — `size` (word count outside `min_tokens`/`max_tokens`), `split_table` (a pipe-table row cut at a chunk boundary), `orphan_heading` (chunk is only a heading, or ends with one), `broken_sentence` (chunk starts mid-sentence with no word overlap from its predecessor in the same source), `missing_metadata` (a configured required field is absent), `encoding_noise` (high control-character ratio, or a repeated line within one chunk). No embeddings, no LLM calls, no optional dependencies — runs in milliseconds per chunk. Verified against the real example corpus, which required adding a new planted chunk (`encoding-noise-1`) that the corpus had been missing entirely for this rule. 24 tests including a real-corpus integration test asserting the exact rule-to-chunk mapping.
- `checks/contradictions.py`: clusters chunks by plain-numpy cosine similarity (0.6 — a looser "same topic" grouping than duplicates' 0.97), extracts `money`/`percent`/`duration`/`date`/`number` facts via priority-ordered regex (each pattern claims its matched span regardless of whether its type is enabled, so a disabled type's digits can't leak through as a bare `number` fact instead), finds each fact's subject via `spaCy`'s `en_core_web_sm` noun-chunk head-lemma, pairs same-subject/different-value/confirmed-different-source candidates, and sends only those to the judge. `CheckContext` gained its deferred `judge` field, typed as a new `JudgeLike` Protocol (not the concrete `JudgeClient`) so tests can pass a lightweight fake judge. Verified against the real example corpus: exactly 1 of 17 chunks' worth of facts reaches the judge. 11 tests plus a real-corpus integration test.
- `adapters/pinecone.py`: list-then-fetch iteration (Pinecone's client has no "page through everything with vectors" call). 11 unit tests against a fake client built from the real installed `pinecone` 10.x package's verified method signatures and response shapes — no live Pinecone index available to test against.
- `adapters/bridge_langchain.py`: wraps an existing LangChain `VectorStore` instance; `count()` raises `NotImplementedError` (the wrapped interface has no enumerate-all/count method at all), `iter_chunks()` falls back to search-based sampling (optional human-provided `sample_queries` plus random-vector probes, deduplicated by id). `VectorStoreAdapter.iteration_mode` (`"full"` | `"sampled"`) added to the Protocol itself for this adapter to report honestly. 13 tests, most against a real `langchain_core.vectorstores.InMemoryVectorStore`.
- `scoring/health.py`: `summarize_findings(snapshot) -> FindingsSummary` + a pure `compute_health(summary, weights) -> int` implementing spec section 11's formula, clamped to `[0, 100]`. `HealthWeights` added to `config.py` as a new `health:` config section. 13 tests covering the full verify-by matrix (every ratio at 0/max, weights over/under 1.0, zero chunks, hand-computed partial ratios). Verified end-to-end against the real example corpus: health 86, hand-recomputed and matched exactly.
- `report/results.py`: `ScanResults`, a real pydantic `BaseModel` wrapping the existing `Snapshot`/`Finding`/`EvalResult` dataclasses directly (pydantic v2 handles stdlib dataclasses as field types natively), with `to_json`/`from_json` round-tripping byte-for-byte stable.
- `report/templates/report.html.j2` + `report/html.py`: the first real HTML report — health score, findings grouped by check and severity via Jinja2's `groupby` filter, `autoescape=True` (verified with a test that chunk text containing `<script>` renders as escaped text, not executable markup).
- `ingest/snapshot.append_findings(path, findings)`: writes findings into an *already-closed* snapshot — the only way checks' findings (which require a `SnapshotReader`, itself only usable post-close) can ever get back into the snapshot that produced them. 4 new tests.
- `cli.py` (second pass): `scan` now runs all 4 built-in checks against the just-written snapshot, computes health, and writes `results.json`/`report.html`. New `kbguard report <snapshot-id>` regenerates both from an existing snapshot's already-computed findings with no adapter connection and no judge call (verified by a test that monkeypatches `load_adapter`/`JudgeClient` to raise if either is touched). Verified end-to-end for real against the example corpus.
- This documentation site (MkDocs + Material), written incrementally alongside the code.
- Repo-root `conftest.py` + `python-dotenv`: `.env` is now loaded automatically before any test runs (confirmed by hand that `load_dotenv()` searches upward from its own file location, not pytest's CWD). `.env.example` documents variable names only, never values; `.gitignore` gained an explicit `!.env.example` exception so the example itself is committed while `.env` stays ignored.
- `tests/test_adapters_pinecone_live.py`: real integration tests against a live, free-tier Pinecone index — seeds and cleans up its own test vectors under a dedicated namespace, exercises `iter_chunks`/`search`/`count`/`collections`/`with_embeddings=False`. Skips cleanly (not an error) when `PINECONE_API_KEY`/`PINECONE_TEST_INDEX` aren't set, same pattern as pgvector/Qdrant's Docker-dependent tests.

### Changed
- `config.py`'s `EmbeddingsConfig` gained an explicit `provider: "sentence-transformers" | "litellm"` field (default `sentence-transformers`) instead of guessing the backend from `model`'s name — a prefix-based guess would misroute valid local HuggingFace models that don't carry a `sentence-transformers/` prefix, and guessing wrong here means document text silently leaving the user's machine via a hosted API. Backward compatible (additive field with a default).
- `pyproject.toml`'s `[tool.mypy]` gained a `[[tool.mypy.overrides]]` entry for optional, lazily-imported extras without type stubs (`sentence_transformers`, `litellm`) — the pattern to extend, not per-call-site `# type: ignore`, as more optional adapters/providers are added.
- `adapters/base.py`'s `search` docstring now states explicitly that results are returned best-match-first — this was true of the Chroma adapter's behavior but hadn't been written into the Protocol itself, which risked a second adapter disagreeing on ordering with no contract forcing consistency.
- `pyproject.toml`'s `[tool.ruff.lint.flake8-bugbear]` gained an `extend-immutable-calls` entry for `typer.Option`/`typer.Argument` — typer's own required idiom for declaring CLI parameters, which ruff's B008 rule otherwise flags as a mutable-default-argument footgun.
- `config.py`'s `StoreConfig.text_field` is now actually wired into adapter `connect()` calls (merged into `**settings` by `cli.py`) — it had been declared in the schema and documented, but nothing read it; Qdrant is the first adapter that genuinely needs it.
- `contract_tests/`'s generic `test_metadata_roundtrips` changed from exact dict equality to a superset check — Qdrant's payload mixes text/id/metadata into one flat namespace, so "nothing extra is mixed in" isn't a promise every backend's storage model can make, unlike Chroma/pgvector's genuinely separate text/metadata storage.
- `pyproject.toml`'s `[tool.mypy]` override for `sentence_transformers`/`litellm` gained `follow_imports = "skip"` alongside `ignore_missing_imports` — the latter only matters when an import can't be found at all; once `sentence-transformers` (pulling in `torch`) was actually installed in this venv, mypy started deeply analyzing its real type surface and hung/crashed (exit code 4, mypy's fatal-error code) instead of reporting a normal result.
- `examples/policy_corpus/`: now 17 chunks, not 16 — added `encoding-noise-1` (payment-methods text with embedded control characters) to give `chunking_damage`'s `encoding_noise` rule a planted example; the embedding basis extended from 13 to 14 dimensions to accommodate it, with all 136 pairwise chunk comparisons re-verified for no accidental collisions. `examples/policy_corpus/kbguard.yaml` gained a `checks.chunking_damage.min_tokens: 10` override (see Fixed, below, for why).

### Fixed (caught before release, not after)
- `chunks.parquet` now uses an explicit schema rather than one inferred from the buffered data — confirmed by hand that pyarrow infers `null`-typed columns from an empty list, which would have given an empty-collection snapshot a schema incompatible with every non-empty one.
- `SnapshotReader.vector()` uses a plain `np.load()`, not `mmap_mode="r"` — memory-mapping worked for row access but kept a file handle open that Windows refuses to delete while mapped, confirmed by hand to break a `pytest` `tmp_path` cleanup with a file-in-use error. Revisit only if vector files actually grow large enough for this to matter.
- Registry test originally relied on `EntryPoint.load()` resolving a real dotted import path, which passed under `python -m pytest` but failed under the plain `pytest` command — fixed by mocking `EntryPoint.load` directly instead.
- Same class of bug recurred in `contract_tests/test_adapter_contract.py` (a top-level `from contract_tests.conftest import ContractCase`, needed only for a type hint) — fixed with a `TYPE_CHECKING`-guarded import plus `from __future__ import annotations`, so it's never evaluated at actual test-run time.
- `cli.py` needed an explicit `@app.callback()` — without it, typer collapses a `Typer()` app with exactly one registered command into a bare top-level command (`kbguard --collection x` instead of `kbguard scan --collection x`), which would have broken the moment a second command (Week 2+) was added, or worse, silently changed every documented usage example retroactively.
- `contract_tests/conftest.py`'s generated collection names used hyphens (`contract-pgvector-...`), which `PgVectorAdapter`'s own identifier allowlist correctly rejects as unsafe to use unquoted in SQL — the fixture naming was wrong, not the validation; switched to underscores, which work for every backend.
- The upfront TCP reachability check for pgvector/Qdrant only proved a port was open, not that *our* service was the one listening there — on this dev machine, an unrelated service already occupied `localhost:5433` (confirmed to be a separate, local Postgres installation, not our container, via `netstat`/`Get-Process`), so the check passed while the real connection then failed with a Postgres auth error. The actual seeding attempt is now also wrapped to skip gracefully on any connection failure, not just the upfront check.
- `docker-compose.yml`'s pgvector port changed from `5433` to `5434` (and the test suite's matching default), moving off the port that collision was on, rather than just working around it in test logic. The remote container was recreated on the new port and re-verified (all 32 Chroma/pgvector/Qdrant tests passing) before the default changed in committed files.
- `tests/test_plugin_registration.py` only ever tested that Chroma's entry-point registration matched its real class — pgvector and Qdrant were built afterward but never got the same real (non-mocked) registration test. Found while adding the equivalent test for `duplicates`; fixed for all three.
- The original architecture spec's `duplicates.minhash_jaccard: 0.9` default was never validated against real paraphrased text before this week — measured directly against the example corpus's near-duplicate pair (word trigrams: 0.0 Jaccard; word unigrams: 0.469) and corrected to `0.3`. See `checks/duplicates.py`'s Added entry above and `docs/guide/checks/duplicates.md`.
- `hnswlib` (one of the two ANN libraries the original spec named) has no prebuilt wheel for this Python/Windows combination and needs a C++ compiler (MSVC Build Tools, not installed) to build from source — confirmed by a failed install attempt, not assumed. Used `faiss-cpu` instead, which installed cleanly with a prebuilt wheel; `pyproject.toml`'s `dedup` extra updated to drop `hnswlib`.
- `checks/stale_versions.py`'s sort-key function originally recomputed a `tuple[int, object] | None` inline inside `sorted()`'s key lambda — mypy correctly rejected both the `None` possibility and `object`'s lack of comparison support. Fixed by precomputing keys into a dict first (filtering `None` where mypy can actually narrow it) and using `Any` for the tier's second slot, since same-tier-only comparison is a runtime guarantee the type system has no way to express, not something worth fighting.
- `checks/chunking_damage.py`'s `orphan_heading` rule misclassified a cut-off table row (`pricing-table-cut`'s last line, `"| Pro | $25/mo"`) as a heading — it's short, has no terminal punctuation, and its one real word is capitalized, so it passed every heading heuristic and was double-flagged alongside the correct `split_table` finding. Found by hand running against the real example corpus, not from a synthetic test. Fixed by excluding any line containing `|` from `_looks_like_heading` before checking the other criteria, with a dedicated regression test.
- The example corpus's chunks (3-25 words each, deliberately tiny for easy hand-verification) all sit under the architecture spec's global `min_tokens: 40` default, which would have flagged nearly every chunk in the corpus as undersized. Not a bug in the 40-word default itself (realistic for production chunk sizes) — fixed with a corpus-local `min_tokens: 10` override in `examples/policy_corpus/kbguard.yaml` rather than changing the global default.
- `docs/guide/evals/judge-and-calibration.md` had already written, before `judge/client.py` existed, that the judge cache makes "re-scanning unchanged data cost zero new LLM calls" — a direct paraphrase of spec section 10's "cached ... in the snapshot" that over-promises once you account for `cli.py`'s `scan` writing a brand-new, differently-named snapshot directory on every run (confirmed by reading `cli.py`, not assumed from the spec wording alone). A fresh scan always gets a cold judge cache. Corrected the doc to state what the cache actually buys: free re-runs of checks/report/diff against the *same* already-written snapshot, not free re-scans.
- `checks/contradictions.py`'s span-consumption originally only ran a regex pattern when its fact_type was in the enabled list — so disabling `duration` let the bare digit inside e.g. `"1-year"` leak through and get reported as a `number` fact instead, the same contradiction resurfacing under a type the user didn't ask to disable. Found by a test that assumed disabling a type meant "nothing extracted at all" and was wrong once run. Fixed so every pattern always claims its span; only whether a fact is *added to the output* depends on the enabled list.
- `pyproject.toml`'s `pinecone` extra depended on `pinecone-client>=4.0`, the original architecture spec's name — that package is now deprecated and raises its own exception on import telling you to install `pinecone` instead. Found by actually installing it while building `adapters/pinecone.py`, not assumed from memory. Fixed to depend on `pinecone>=5.0`.
- `ContradictionsCheckConfig.enabled` defaulted to `true`, inherited from the other three checks' pattern without accounting for the fact that this check, uniquely, cannot do anything at all without a configured judge — found during `cli.py` integration, where it would have made every existing scan with no `judge:` configured raise `ContradictionsCheckError`. Fixed by flipping the default to `false`, matching this project's own stated "judge-dependent features stay off until configured" principle (already written into `docs/guide/configuration.md` before this check existed).
- `adapters/pinecone.py`'s `collections()` called `self._require_client().list_indexes().names` as a plain attribute. It compiled, type-checked, and passed all 11 fake-client unit tests, because the fake was built to the same wrong assumption from reading `dir(IndexList)` output without checking whether `names` was callable. Only running the real adapter against a real, live Pinecone index (set up specifically to close this gap) surfaced it: `TypeError: 'method' object is not iterable`. `IndexList.names` is a method (`names()`) on the real installed client. Fixed in both the adapter and the fake unit-test client, so the fake can't silently regress to the same wrong shape again — this is the concrete example of why "unit-tested against a fake client" and "verified against the real thing" are different claims, worth keeping distinct in docs rather than treating as equivalent.

### Design decisions locked in
- Read-only access to vector stores, with no write code path in any adapter.
- Adapters and checks are `Protocol`-typed plugins, discovered via `importlib.metadata` entry points.
- `Finding.fingerprint = sha256(check + sorted(chunk_ids) + sorted(identity_keys))[:16]`.
- Health score formula clamped to `[0, 100]` regardless of configured weights.
- `kbguard diff --against <baseline> [--snapshot <new>]` as the single CLI form (replacing an earlier spec draft that showed two inconsistent forms).
- `examples/policy_corpus/`'s embeddings are hand-crafted and verified by hand against the real default duplicate threshold, not produced by a real embedding model — see the corpus's own README for why.
- Test infrastructure (Docker) doesn't have to be local — the test suite's connection host is always environment-variable-overridable, never assumed to be `localhost`, specifically to support a remote Docker engine reached via `DOCKER_HOST=ssh://...`.
- Duplicate detection requires **both** cosine similarity and MinHash word-Jaccard to pass — neither alone, since each has a confirmed real false-positive mode the other one closes (same-topic-different-wording for cosine alone; the stale-version pair's single-word difference for Jaccard alone).
- A chunk already reported as an exact duplicate is excluded entirely from near-duplicate detection, rather than deduplicating overlapping findings afterward — an exact-duplicate pair would trivially pass both near-duplicate thresholds too (cosine=1.0, jaccard=1.0).
- Cross-source duplicate findings escalate to `error` unconditionally, overriding whatever base severity was configured for the check — specifically because spec calls cross-source duplication out as more significant (real copy-pasted content) than within-document duplication, not just "whatever severity the user happened to set".
- `stale_versions`' self-retrieval probe queries the *live* store, not the snapshot — the one check so far whose severity depends on something other than static snapshot data. Without a live adapter/collection in `CheckContext`, the check still works, just without escalation, rather than failing outright.
- A document family member with neither `updated_at` nor `version` is excluded from stale-version ordering entirely, not guessed at — same "don't claim confidence you don't have" principle as the LangChain/LlamaIndex bridge's `iteration_mode` flag.
- `chunking_damage`'s "token" count is a plain whitespace split, not a model-accurate tokenizer (tiktoken) — kept intentionally cheap and dependency-free, with the approximation stated explicitly in each finding's evidence rather than silently implying a model-accurate count.
- `chunking_damage`'s `broken_sentence` rule gives a chunk with no identifiable predecessor (missing `source`/`position`, or no sibling at `position - 1`) no benefit of the doubt — it's flagged as broken, since "can't confirm deliberate overlap" isn't the same guarantee as "confirmed no overlap."
- `chunking_damage`'s control-character threshold (1% of characters) is a judgment call, not measured against a real corpus of corrupted documents the way `duplicates.minhash_jaccard` was — no such corpus was available this week. Documented as unvalidated rather than presented as calibrated.
- `JudgeCache` is scoped to one snapshot's own directory, not shared across separate `kbguard scan` runs — a deliberate, narrower reading of spec section 10's "cached ... in the snapshot" than a naive "caches the judge globally" would be, chosen because that's what the phrase literally supports given snapshots are per-scan, immutable, and separately named.
- `JudgeClient.ask_json` only retries on a JSON parse failure, never on a provider/network error from `litellm.completion` itself — those propagate immediately rather than being silently retried or swallowed, since a retry loop is meant for "the model answered but not in the shape we asked for," not for masking a real API failure.
- `contradictions` candidate pairs require *confirmed* different sources (both non-`None` and unequal), not just "not provably the same" — two chunks from the same document family (different version, same `doc_id`) are excluded even though they're same-subject/different-value, since that's `stale_versions`' finding to make, not a second, redundant contradiction.
- `contradictions`' embedding clustering (0.6 cosine) is plain numpy, not an ANN index — a real v0.1 scaling limit on a very large corpus, documented explicitly rather than hidden, unlike `duplicates.py`'s faiss-backed near-duplicate search which was built for that scale from the start.
- `bridge_langchain`'s random probe vectors use a fixed seed (0) — sampling coverage should be reproducible between two scans of an unchanged collection (so a future `diff` isn't just sampling noise), not a source of real randomness.
- `scoring/health.py`'s three per-chunk ratios count *distinct* flagged chunk ids, not raw finding counts — a chunk flagged by two separate findings from the same check (e.g. `chunking_damage`'s `size` and `orphan_heading` both firing on one chunk) must only move the ratio once.
- `report/html.py` uses `autoescape=True` explicitly — jinja2's own default is `autoescape=False`, and finding messages/evidence can contain text pulled straight from a client's own documents, which this project treats as untrusted.
- `cli.py`'s `report` command reads the full `kbguard.yaml` (for `health:` weights) but never calls `adapter.connect()` or constructs a `JudgeClient` — parsing the config for convenience doesn't mean touching the network or a credential it was never going to use.
